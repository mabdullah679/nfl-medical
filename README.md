# NFL Medical Data Platform: local pipeline test harness

A Docker-based stand-in for a healthcare-style reporting pipeline (MySQL source, change capture into
PostgreSQL, ingestion, Parquet extraction, report generation, SFTP delivery, all orchestrated by Airflow),
driven by a Bruno collection that checks every stage and deliberately breaks things to prove failures are
noticed and alerted. All data is synthetic, generated by [infra/sql/04-seed.sql](infra/sql/04-seed.sql).

It tests the pipeline's contract against a requirements specification before anything is built in AWS. It is
not the production pipeline, and a green run here does not show that an AWS deployment works. What each
requirement is and is not proven by: [docs/COVERAGE.md](docs/COVERAGE.md).

```
Bruno collection ──▶ shim :8096 (read-only checks)      dms-stub :8098 (DMS-shaped API)
        │                 │ reads everything below
        ▼                 ▼
mysql ─binlog─▶ kafka-connect (Debezium) ─▶ kafka ─▶ kafka-connect (JDBC sink) ─▶ postgres staging
                                                                                      │ nfl_ingestion
airflow :8095 ── nfl_extraction ─▶ Parquet + manifest + _SUCCESS ─▶ floci S3 ◀── postgres utm
              └─ nfl_reporting ─▶ report + .sha256 ─▶ sftp :2225
watch (probes every 15 s) ─▶ alerts ─▶ mail :8094 (local inbox)      logship ─▶ floci CloudWatch Logs
```

Not local and not started by this project: **floci**, the local AWS emulator, must already answer on
`http://localhost:4566`. Apache Hop, Spark, AWS DMS, a dashboard and a real alert channel are not in the
stack at all (Debezium, Python and SQL inside Airflow tasks, and a local mail server stand in).

## Prerequisites

- Docker with compose v2 or later (the run notes in [docs/RUNBOOK.md](docs/RUNBOOK.md) were measured on Docker 29.8.0)
- `python3`, `curl`, `lsof`, `ssh-keygen` on the host (`scripts/init-env.sh` and `scripts/up.sh` stop with a named error if one is missing)
- floci answering on port 4566, started separately
- The `bru` CLI to run the collection from a terminal: `npm install -g @usebruno/cli`
- Free host ports 3307, 5440, 8094, 8095, 8096, 8097, 8098, 9099, 2225 (all bound to 127.0.0.1)

The host does not need Java, Maven, Node (except for `bru`), or any database client.

## Run it

Use bash or zsh. Steps are identical on macOS and Linux; the scripts are bash and are not written for Windows.

1. Confirm floci is up: `curl -fsS http://localhost:4566/_localstack/health`
2. Generate secrets and SFTP keys (once; it refuses to overwrite): `scripts/init-env.sh`
3. Start the stack (idempotent): `scripts/up.sh`. Exit 0 and the closing line "Stack is up" mean every service is healthy and every check identity authenticated (about 100 s cold).
4. Run the collection:
   ```bash
   cd bruno
   set -a; . ../infra/nfl.env; set +a
   bru run -r --exclude-tags chaos --env local \
     --env-var "airflow_password=${AIRFLOW_ADMIN_PASSWORD}" \
     --env-var "aws_secret_access_key=${AWS_SECRET_ACCESS_KEY}"
   ```
5. Optionally run failure injection, after a green normal run: `bru run 90-chaos --env local` with the same two `--env-var` flags.
6. Stop with `scripts/down.sh` (keeps data) or wipe with `scripts/reset.sh -y`.

Do not start the stack with a bare `docker compose up`: it skips the env file, the bucket, the grants and the connectors.

If something fails: [docs/RUNBOOK.md section 5](docs/RUNBOOK.md#5-when-upsh-fails). If a port is taken, `up.sh`
stops and names it; ports are set in `infra/nfl.env`, template [infra/env.example.txt](infra/env.example.txt).

Step-by-step with an explanation of every command: [FROM-NOTHING.txt](FROM-NOTHING.txt).

## What it does

| You do | You get |
|---|---|
| `scripts/up.sh` | 12 containers, schemas, roles, grants, both Debezium connectors registered, seeded source rows replicated into Postgres staging |
| `bru run` (normal) | August 2026 driven through ingestion, extraction, reporting and SFTP delivery, then events, alerts, watcher and logs checked |
| `bru run 90-chaos` | Ten failures injected one at a time; each is checked as noticed and alerted, then restored |
| Open http://localhost:8094 | The Operations inbox: every alert email, newest first |
| Open http://localhost:8095 | The Airflow UI (user `nfladmin`, password `AIRFLOW_ADMIN_PASSWORD` in `infra/nfl.env`) |

Seeded "bad rows" (null and duplicate business keys, an orphan transaction) are there on purpose so the
quality gate has something to reject; they are tagged BAD-1 to BAD-7 in [infra/sql/04-seed.sql](infra/sql/04-seed.sql).

Last recorded Bruno results, from [FROM-NOTHING.txt](FROM-NOTHING.txt) (2026-10-07, not re-run when this README was written): normal run 109 requests / 344 tests, chaos run 86 requests / 233 tests.

## Interfaces

All on 127.0.0.1.

| Service | Port | What | Auth |
|---|---|---|---|
| shim | 8096 | `GET /health`, `GET /checks` (index), `GET /checks/*` read-only checks | none from the host; each check connects to its backend as its own least-privilege identity |
| dms-stub | 8098 | DMS control-plane API (`awsjson1.1`), status derived from the Debezium connector state | none |
| airflow | 8095 | UI and REST API | basic, `nfladmin` |
| kafka-connect | 8097 | Connect REST API | none |
| mail | 8094 | Mailpit web UI and API | none |
| mysql / postgres / kafka / sftp | 3307 / 5440 / 9099 / 2225 | source DB, `nfl` DB, broker, delivery target | generated secrets in `infra/nfl.env` |

The full list of shim routes is `curl -s localhost:8096/checks` on a running stack, and
[shim/README.md](shim/README.md).

## Tests

What ran without the stack (these are what CI runs, see [.github/workflows/ci.yml](.github/workflows/ci.yml)):

```bash
python3 -m compileall -q docs infra/airflow/dags scripts shim stub watch
python3 docs/check_coverage.py --check          # coverage doc recounts and its Bruno/DAG citations resolve
docker compose --project-directory infra -f infra/docker-compose.yml --env-file infra/env.example.txt config --quiet
docker build -t nfl-dms-stub stub && docker run --rm nfl-dms-stub python selftest.py   # 78 checks, 0 failures
```

The Bruno collection (`bruno/`, 210 files, 8 folders) is the end-to-end suite. It needs the full stack and
floci, so it is **not** run in CI. `python3 docs/check_coverage.py --live` also checks shim routes against a
running shim.

## Design decisions worth knowing

- **Debezium does the real change capture; only the DMS control plane is stubbed.** floci does not implement DMS, so the stub answers in DMS's shape with its status derived from the connector. A fully faked DMS would prove nothing about replication ([D-003](docs/DECISIONS.md)).
- **The env file is `infra/nfl.env`, not `.env`.** The maintainer's Claude Code tool permissions deny every `.env*` path, so a script depending on one could not be verified by the sessions that maintain it. Side effect: every script passes `--env-file` explicitly and a bare compose command fails on the first required variable ([D-007](docs/DECISIONS.md)).
- **One Postgres role per check.** The shim connects as a different least-privilege identity for each check instead of one shared account, so a check cannot read more than it reports ([D-010](docs/DECISIONS.md)).
- **The watcher is its own container, not an Airflow DAG**, because the orchestrator is one of the things it watches ([D-014](docs/DECISIONS.md)).
- **Ports bind 127.0.0.1 only** ([D-011](docs/DECISIONS.md)).
